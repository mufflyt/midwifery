# Technical Appendix: Contested NPIs and the One-to-One Constraint

**Repository**: `midwifery`
**Primary code**: [`match_amcb_to_npi.R`](../match_amcb_to_npi.R),
[`R/amcb_match_rules.R`](../R/amcb_match_rules.R) (`amcb_award_contested()`)
**Imported resolver**: `rank_one_to_one()` from `~/isochrones/R/npi_resolution.R`
**Gate**: G8 in [`tests/test_amcb_gates.R`](../tests/test_amcb_gates.R)
**Investigation date**: 2026-08-30

---

## 1. What a contested NPI is

Individual resolution runs first: each certificant is compared against the
candidate pool on her own, and resolves when exactly one candidate occupies her
strongest evidence class. Only afterwards is one-to-one enforced, because
identifiability is a property of one person's evidence and must not depend on
another person's claim.

A **contested** NPI is one that two or more certificants each resolved to
independently. It is not a matching error. It is two people whose name evidence
points at the same provider record, and it is a data-quality signal in its own
right — which is why the count is taken before the constraint prunes anything.

## 2. The change that prompted this appendix

`rank_one_to_one()` is imported from another repository. Until 2026-08-08 it
consumed NPIs greedily: rows were sorted on `(method_priority, score_total,
confidence_score, id)` and each NPI went to the first claimant, so a contested
NPI produced one winner and one loser. On 2026-08-08 that was removed. The
commit's own reasoning:

> A score gap is not by itself evidence that the higher scorer is the right
> person, and adding a second scientific rule here would make the transition
> audit uninterpretable. Whether a dominance rule is warranted is an empirical
> question for later.

Both claimants are now quarantined. The effect on this cohort, measured by
re-running the pipeline unchanged against the same panel:

| | frozen (2026-08-10) | re-run, unchanged code |
|---|---|---|
| `ambiguous_contested_npi` | 95 | **188** |

**93 certificants were withdrawn from the cohort by a change in a different
repository, with no change to this pipeline and no error raised.** The frozen
cohort of 16,892 cannot be regenerated by running the current code; that is
recorded here rather than discovered again later.

## 3. The empirical question, answered

The upstream note left the dominance rule as "an empirical question for later."
It is answerable directly, because the evidence class of every claim is
recorded. Over the 93 contested NPIs (188 claimants, 91 two-way and 2 three-way):

| | NPIs |
|---|---|
| one claimant holds **strictly stronger** name evidence than every rival | **56** |
| claimants **tie at the same evidence class** | **37** |

The 37 break down as 10 tying at class 1 (exact surname, exact given name, *and*
a corroborating middle name on both sides), 19 at class 2, and 8 at class 3.
A class-1 tie is two certificants whose full names and middle initials both
match one provider record. No ordering of that evidence exists.

So the choice is not "recover 93" against "recover 0":

| rule | recovered | identities decided by sort order | contested remaining |
|---|---|---|---|
| `quarantine_all` (upstream default) | 0 | 0 | 188 |
| **`strict_dominance`** (this pipeline's default) | **56** | **0** | **132** |
| `greedy` (pre-2026-08-08 behaviour) | 93 | **37** | 95 |

### 3a. What the shipped pipeline actually produced

The table above is measured on the **control** run — the pipeline with no other
change — so that the effect of the award rule alone is visible. The shipped
pipeline also carries the middle-name token-set fix, which runs first and
resolves records that would otherwise have reached the bijection, shrinking the
contested set before any award rule sees it:

| run | middle-name rule | award rule | contested |
|---|---|---|---|
| control | position-1 | `quarantine_all` | 188 |
| middle-name fix only | token sets | `quarantine_all` | 176 |
| **shipped** | token sets | **`strict_dominance`** | **123** |

So the award rule recovers **53** NPIs in the shipped configuration, not the 56
projected from the control, and 123 rows remain contested rather than 132. Both
figures are real measurements on different candidate sets; neither supersedes
the other, and quoting the 56 as the shipped result would be wrong.

Cumulative effect of both changes against the control: **+185 matched, +153
cohort members, tied down 95, contested down 65.**

## 4. The rule this pipeline uses

`amcb_award_contested()` awards a contested NPI to a claimant whose evidence
tuple `(method_priority, score_total_adj, confidence_score)` is strictly better
than the runner-up's. When the leader and runner-up share that tuple, the NPI is
awarded to nobody and both claimants stay quarantined.

This takes every record the evidence can justify and none that it cannot. The
37 are a genuine tie: two people, one provider record, identical name evidence.
Handing that NPI to the lexically smaller certification number is not a linkage
result, and it is invisible downstream — the surviving row looks exactly like a
resolved match. This is the same failure mode the class-5 guard exists to
prevent (see
[`TECHNICAL_APPENDIX_RECORD_LINKAGE.md`](TECHNICAL_APPENDIX_RECORD_LINKAGE.md)
§5): a claim that was not ruled *in*, merely not ruled *out*.

`greedy` remains reachable via `CONTESTED_RULE=greedy`, because reproducing the
frozen 16,892 requires it and a published number nobody can regenerate is worse
than one whose weakness is written down. **It is not the default**, and any
result produced with it should say so.

## 5. Why this is not decided by taxonomy or geography

Two temptations, both refused for the same reason as the tie rule in §5 of the
record-linkage appendix.

**Taxonomy cannot break the tie.** That one claimant's candidate carries a
midwifery taxonomy and the other's carries nursing says what the NPI does for a
living, not which of two people it belongs to.

**Geography cannot break it either.** The AMCB roster publishes no state,
address or licence number — §1 of the record-linkage appendix — so there is
nothing on the roster side to compare a practice location against. A rule using
the NPPES address would be comparing the candidate to itself.

## 6. Reproducing this

```
CONTESTED_RULE=strict_dominance Rscript match_amcb_to_npi.R   # default
CONTESTED_RULE=quarantine_all   Rscript match_amcb_to_npi.R   # upstream behaviour
CONTESTED_RULE=greedy           Rscript match_amcb_to_npi.R   # pre-2026-08-08
Rscript tests/test_amcb_gates.R                               # G8 pins all three
```

G8 asserts that `strict_dominance` awards the separable NPI, **refuses the exact
tie**, that `greedy` awards both, and that an unknown rule name errors rather
than silently quarantining. The refusal is the assertion that matters: a rule
that awards the tie is the defect, not the fix.

## 7. What is still open

The 37 inseparable NPIs are a real finding about the roster, not a defect to
tune away. Each is two certificants and one provider record. Two readings, and
the data here cannot distinguish them:

- two people genuinely share a name and one of them is absent from NPPES, or
- NPPES holds one record for what should be two enumerations.

Separating those needs an identifier neither source publishes — a licence
number, a date of birth, or a practice address on the AMCB side. Until then
they are correctly reported as ambiguous rather than resolved.
