## Found broken during this audit, now fixed

**The cycle-1 RUCC defect survived in two root-level scripts.**
`build_county_midwifery_supply.R:193` and `calibrate_osmde_vs_ec2.R:84` both
still carried `TRUE ~ "Nonmetro, remote (RUCC 7-9)"`, which labels any
unexpected code — 0, 10, a 99 "not classified" sentinel — as remote. Cycles 1,
2 and 5 all swept for this and every sweep scanned `R/`, never the root
scripts. The first of those files writes a **published artifact carrying a
rurality column**.

Both now call `band_rurality()`. Behaviour preserved: **0 of 3,235** labels
changed, because the current RUCC vintage is clean 1–9 with two NA. Latent,
exactly as in cycle 1 — and it would fire on the first vintage using a sentinel.

## Newly exercised, previously code-only

C14a and C14b had never run in production. The map was rebuilt for this audit
(435 MB of isochrones, 52 water masks) and both fired:

```
[nesting]    WARNING 30min escapes 60min by 84 km2 (0.002% of the outer band)
[land clip]  applied=TRUE masks=49/49 final=TRUE
```

The 84.1 km² escape is **real routing-engine disagreement, now recorded rather
than absorbed**. Under the pre-fix code it was destroyed by the same statement
that hid it. It is small — 0.002% — which is itself worth knowing: it bounds
how much the EC2/osm.de mixture distorts the published bands.

The same run surfaced a separate pre-existing data problem, correctly handled:
**5 water masks (AR, IA, KS, MO, WV) are state outlines, not water** — 45× to
162× their census water area. They are excluded with the reason printed;
subtracting them would erase every polygon in those states.

## Not fixed — one residual, scoped precisely

`C9b` reports 10 duplicated functions, 7 divergent. **Only one can collide.**
Files must share an environment for load order to matter, and only
`enrich_healthgrades_profiles.R` sources a file (`scrape_healthgrades_midwives.R`)
that defines the same name — `main`. The enrichment script deliberately
overrides it, which works because its definition follows the `source()` call.

The hazard is real but latent: move that `source()` below the definition and
running the enrichment script would run the **scraper** instead. Not fixed
today because the sweep is mid-crawl with that file sourced, and destabilising a
12-hour run for a naming hazard is the wrong trade. **Phase 2 item:** rename to
`enrich_main()`.

The other nine duplicates live in standalone scripts that never share an
environment. Residual risk, not a live collision — the cycle-9 fix held for the
numbered pipeline it targeted.

## Audit method note

Two of the three audit passes were themselves parsed rather than grepped, after
the run demonstrated four times that text detectors are wrong in both
directions. The duplicate and join checks read `parse()`d code and inspect
argument names.

## What this exercise demonstrated about auditing

Each pass found defects in the pass before it. The fix audit found a defect the
21 cycles missed (two root-level RUCC copies). Testing the fix audit found a
defect the audit introduced (the shebang) and one it duplicated (the Hall of
Shame entry). Re-auditing found that my correction restated an existing account
rather than referencing it.

The pattern is consistent and worth carrying into Phase 2: **a verification
step is itself unverified work.** Nothing here was caught by the suite — all of
it came from checking the thing that did the checking.
