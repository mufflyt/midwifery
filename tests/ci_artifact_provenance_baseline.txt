# Tracked artifacts with no .provenance.json sidecar.
#
# Same rule as tests/ci_leak_baseline.txt: may shrink, must never grow. A3 used
# to hold a COUNT (MAX_UNCOVERED). A count says how much debt exists; it does
# not say which files, so it cannot tell a new uncovered artifact from an old
# one when the total happens to stay flat, and the only way to record a real
# reduction is to edit the number -- which looks identical to raising it.
#
# WHY THESE CANNOT SIMPLY BE FIXED. Twenty of them were added on 2026-08-13/14
# by the state-board-of-nursing work. Every producing script reads one of the
# eight person-level master files that #38 untracked, and those are gitignored
# by design and absent from every checkout. So the artifacts cannot be
# regenerated -- not in CI, not in a fresh clone, not locally without re-running
# live multi-state portal scrapes that would return different data. Their
# inputs+sha256 cannot be recovered, only re-recorded at production time by
# whoever runs the pipeline next.
#
# There is also no Python path to provenance: write_with_provenance() exists
# only in R/lib/artifact_provenance.R, and 13 of the 20 producers are Python.
# Until that gap is closed, "write it through write_with_provenance()" is not
# advice a Python producer can follow.
#
# Removing a line requires the artifact to gain a real sidecar -- inputs and
# their SHA-256 as recorded when it was written, not reconstructed afterwards.
