# Full-width reads of midwife_panel.csv that existed when tests/ci_read_width.R
# was written (2026-11-21). Format: path <TAB> count <TAB> reason
#
# THIS FILE SHOULD ONLY SHRINK. Each count is that many full parses of a 544 MB,
# 4,735,546-row, 13-column CSV in order to keep a handful of columns. Measured
# (Review_AI_performance.qmd, one process per arm, /usr/bin/time -l):
#
#   read_csv(cols(.default = "c"))        60.8s     534 MB held
#   read_csv(col_select = <3 used>)       12.1s     137 MB held   identical()
#
# Deleting a line is the fix: pass col_select = c(<the columns the script uses>)
# and delete the row. Raising a count is a decision to parse ten columns nobody
# reads, and needs the same justification any other waste would.
#
# The counts here total 28 reads across 24 files. Fourteen of these scripts are
# named in rebuild_frozen_dependents.R's plan and account for 18 of the reads,
# so one REBUILD_APPLY pass spends an extrapolated 18.2 minutes in readr on this
# one file -- against 3.6 minutes if every read named its columns.
#
# WHAT THE REASONS MEAN
#   PROVABLE   the read's own pipeline transmute()s or transmute-equivalents to
#              a fixed, named column set in the next statement, so the columns
#              it needs are not a guess. Narrow these first.
#   WIDER      the chain filters and keeps going, so the full set of columns the
#              script uses has to be read before narrowing it. Narrowing is
#              still almost certainly right, but it is not a one-line change
#              that can be made without reading the script.
